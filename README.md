# GPT Speak

基于 NapCat / OneBot 的 QQ 群聊 AI Bot，包含 CLI、WebUI、图片理解、共享表情库、群记忆、知识库和按群覆盖的配置。

项目名称为 **GPT Speak**。默认采用 GPT 6 Luna 白龙娘设定，参考部署者的“白色大肥龙”配置：角色名 Luna／露娜，银白长发、白色弯角、淡紫眼睛、膜翼与白鳞长尾，语气自然清淡、略带慵懒；句尾通常不用句号。默认显示名“白色大肥龙”，支持 Luna、GPT 6 Luna、露娜、白龙娘等别名。角色设定不替代实际模型选择，模型仍由配置决定。

项目地址：[3035936740/GPT-Speak](https://github.com/3035936740/GPT-Speak)。WebUI左侧“命令行”下方的“关于”可查看项目介绍并打开GitHub项目页。

新安装从 `persona-default.txt` 和 `reply_protocol-default.txt` 初始化人设与回复规则，两份合计约2600字。已有全局或群级人设、别名和连接配置继续保留，不导入示例中的群号或连接凭据。WebUI与CLI使用GPT Speak品牌，群内角色名按当前配置显示。

## 群聊接话

当前群顶部“仅接收消息 / 恢复AI处理”或CLI `/receive on|off` 控制 `receive_only`，默认关闭。仅接收时保留NapCat群连接和聊天记录，跳过AI回复、图片识别/生成、学习、主动话题和消息发送；切换时取消当前生成、待回复和待发送队列。恢复后只处理后续新消息，期间收到的内容仅作历史背景，不补答。该设置按群保存，重启保留，也随完整设置包导出；不改变白名单、其他群或群启用状态。

“行为设置”顶部提供完整设置JSON的导入/导出：包含全局行为配置、人设与回复规则、群白名单与启用开关、每群独立配置/提示词、群友类型/昵称/说明/屏蔽标记和无冷却开关。导入先预览，点击保存并确认才应用；恢复继承的提示词会移除原群独立文件。应用前备份到 `config-backups/bundle-*/`，失败自动回滚；预览后设置变动须重新预览。文件包含WebUI密钥与NapCat连接凭据，请妥善保管。连接地址/令牌默认保留本机值，可在导入预览中选择恢复；仅恢复NAPCAT_HOST/NAPCAT_TOKEN，不覆盖.env其他内容。本机主群编号、Codex路径和.env路径保留，避免群运行数据关联错位；聊天存档、记忆数据库、知识库和表情文件不属于设置包。导入后退出并重启控制台加载完整设置。

重启恢复的消息只作为已读历史存档，不重放旧@、待回复队列，也不重新识图、学习或触发主动话题。供新问题参考时，历史在输入预算内合并成 `history_archive` 一段只读文本；新聊天消息才进入正常处理流程。

WebUI当前群提供“终止当前会话 / 恢复当前会话”和“清空对话上下文”。对应CLI为 `/session stop`、`/session resume` 和 `/session clear`：stop取消当前生成/待发送回复并持续暂停接话，resume恢复后只处理新消息；clear取消当前任务并清除短期上下文和对话焦点，保持当前暂停状态。只影响当前群，聊天存档、群记忆和知识库保留。暂停与清空边界持久化，重启不会处理暂停期间积压的消息；已经发送或已提交QQ接口的消息不能撤回。

启动和停止群后台以 `instance.lock` 的实际锁占用为准，不把状态文件中的旧PID视为实例凭据。系统可能把退出bot的PID分配给其他程序；这种情况不会阻止重新启动，也不会操作该无关程序。WebUI会将没有实例锁的旧运行状态显示为“后台未运行”。

消息接收只补有限的最近记录，不要求完整同步历史。启动历史查询最多等待5秒，失败跳过；日常历史查询同样有5秒期限，明确从最新位置读取。历史不再前进时每30秒检查最近会话，通过单条消息接口补读当前群最新一条；历史接口失败时立即尝试该路径。所有新到达消息先写入聊天事件记录，再处理引用、识图与回复；引用补读最多2秒。旧记录缺失不会阻止之后接收新消息。WebUI中群后台超过两分钟没有轮询心跳时显示“刷新停滞”。

群聊的 `high_eq_enabled`（高情商接话）默认开启，也可在“行为设置 → 参与群聊的节奏”按群关闭。它让现有上下文/情绪分析联合理解同一人的连续评价，区分评价自己与评价第三方；回复层避免被批评后自夸辩解，保留正常玩梗、事实纠正与边界。关闭使用 `/config set high_eq_enabled off`。不新增固定模型调用；仅当候选被质量检查发现问题时，使用既有调用预算尝试一次改写，没有合格候选则保留现有静默策略。参考了 MaiBot 的反馈关联与分离表达风格的思路，未移植其代码或提示词。

## 知识库

WebUI 当前群的“知识库”支持手动录入、导入任意扩展名的文本文件、搜索、查看编辑、停用和删除，包括 TXT、Markdown、YAML/YML、JSON/JSONL、INI、TOML、XML、CSV、日志、代码和无扩展名文件。支持 UTF-8、带 BOM 的 UTF-16 及 GBK/GB18030，不限制文件大小和正文字数；文本按原样保存，保留缩进和换行，不执行代码或展开配置。导入后先预览编辑，点击保存才入库。每篇可选择“仅当前群”或“所有群共享”，私有知识不会提供给其他群。内容保存在 `group-bot/runtime/knowledge.sqlite3`，编辑删除前自动备份到 `runtime/knowledge-backups/`，迁移时一起保留。

回复前使用本地英文词及中文双字索引检索全部匹配片段，附带标题和来源；`knowledge_max_chars` 默认0，不设知识库检索字符数或结果条数上限。仍受模型总输入上限限制，空间不足时优先保留排名靠前的参考片段；可改为至少200的正整数设置单独预算。它不额外调用模型，不自动收录群聊。知识内容作为参考资料处理，不作为系统指令。`knowledge_enabled` 默认开启，两项支持按群覆盖；停用某篇后立即停止检索该篇。当前支持文本资料，不包含PDF/Word解析或向量嵌入。

共享表情库和全局行为设置中提供“表情总开关”（`stickers_enabled`，默认开启）。关闭后停止发送表情以及自动、手动收录，已有表情保留；普通图片识别、聊天和绘图继续可用。每张表情的“永久排除”会删除库内原图与预览，按完整 SHA256 记录到 `shared-emoji-library/excluded.json`；同图改名、跨群重复出现、人工上传或迁移旧库均不能重新入库。QQ 商城表情按原生表情标识排除。名单不随普通拒绝记录清理，迁移项目时需一并保留。

CLI `/knowledge` 列出可用知识，`/knowledge 查询内容` 预览本地检索结果，不发送QQ群消息；新增和管理请使用WebUI。

回复路由会先把当前问题命中的知识库片段交给上下文判断，已有资料足够覆盖的问题直接回答；联网失败时有相关本地资料且额度允许，可退回一次本地知识回答，不伪装联网成功。联网证据只接受已完成的工具事件或本轮已实际读到的匹配页面；缺失时记录事件类型统计，不记录模型原始思考。

`forward_messages_enabled` 默认开启，群聊中的合并转发卡片显示为“聊天记录”，按原顺序将全部原消息的日期时间、发送者与正文合为一条历史引用，明确标注非实时话题；其中的@、链接和指令不会自动变成当前请求。WebUI 显示前4条、每条20字的预览和总条数，右侧通过单独接口读取完整正文。`forward_images_enabled` 默认关闭，内部图片只作 `[图片]` 占位；开启后才允许识图，仍受现有图片和模型预算控制。正文缓存保存在各群 `runtime*/forward-messages/`，模型输入仍受总上下文上限约束。

## 运行环境与安装入口

Bot 支持 Windows / Linux / macOS，Python 3.10+；安装脚本使用 uv 安装独立 Python 3.12 和项目 `.venv`。模型需要本机已认证、可运行的 Codex CLI；安装脚本不包含账号登录、模型授权或自动设置群白名单。

根目录保留两类启动入口，以及两个安装入口。四者均提供 `.ps1`、`.cmd`、`.bat`、`.sh`：

| 入口 | 用途 |
| --- | --- |
| `Start-QQ-Group-Bot` | 默认启动 Debug CLI + WebUI，替代原 `Start-QQ-Group-Bot-Debug` |
| `Start-QQ-NapCat` | 启动已配置的 NapCat；已有本机 WebUI 时避免重复启动 |
| `Install-Environment` | 安装项目 Python、第三方依赖；初始化缺失配置，保留已有配置和人设 |
| `Install-NapCat` | Windows 官方 OneKey 安装包；Linux/macOS 使用官方 Docker 镜像 |

旧顶层启动/停止脚本归档到 `ignore/launchers/`，保留原内容供查阅，不作为新入口。`ignore/`、`tools/`、`.venv/`、`launch.local.json`、运行数据和凭据均不纳入 Git。上游 QQ MCP 及 NapCat 内部自己的脚本保留原位置。

## 首次安装

Windows 双击 `Install-Environment.cmd`（或 `.bat`）；随后运行 `Install-NapCat.cmd`。PowerShell 也可执行：

```powershell
.\Install-Environment.ps1
.\Install-NapCat.ps1
.\Start-QQ-NapCat.ps1
```

Linux/macOS 在项目目录执行：

```sh
sh ./Install-Environment.sh
sh ./Install-NapCat.sh
sh ./Start-QQ-NapCat.sh
```

环境安装从 [uv 官方来源](https://docs.astral.sh/uv/getting-started/installation/)下载工具到 `tools/uv/`，下载 Python 后创建 `.venv`，安装 `requirements.txt` 并检查依赖。若已有 `qq-mcp/pyproject.toml`，同时安装其依赖；Bot 直接调用 OneBot HTTP，不要求额外启动 MCP 服务。已有 `.venv` 不会删除或重建。脚本失败时返回非零退出码，可以重试。

NapCat 安装来源遵循 [官方安装说明](https://napneko.github.io/guide/boot/Shell)：Windows x64 下载 `NapCat.Shell.Windows.OneKey.zip` 后运行官方 `NapCatInstaller.exe`（按其提示完成 QQ/NapCat 安装）；Linux/macOS 需先安装并启动 Docker Engine/Desktop 与 Compose v2，脚本生成持久化 Compose 并拉取 `mlikiowa/napcat-docker:latest`，支持 amd64/arm64。Windows 也可使用 `Install-NapCat.ps1 -Backend docker`。macOS 当前提供 Docker 入口，不自动修改本机 QQ.app。安装和启动分开，不会在安装后自动发消息。

已有 `launch.local.json` 时安装器保留它，不覆盖已有 NapCat。可复制 `launch.local.example.json` 为 `launch.local.json` 并填写已有 Windows Hook 安装路径；路径相对项目根目录，也支持绝对路径。安装器生成的路径默认相对根目录。迁移时仍需保留 QQ/NapCat 的实际目录或更新此本机配置。

首次设置：

1. 在 NapCat WebUI `http://127.0.0.1:6099/webui` 登录 QQ，开启 OneBot HTTP，配置访问令牌。Docker 模式在容器内监听 `0.0.0.0:3000`，主机仅映射 `127.0.0.1:3000`；WebUI 和 WS 端口也仅映射到本机。随机 WebUI 令牌保存在本地 `runtime/napcat-docker/compose.json`。
2. 新安装填写 `group-bot/napcat.env` 的 `NAPCAT_HOST` 和 `NAPCAT_TOKEN`。已有安装继续使用 `settings.json` 的 `mcp_env_file`，例如 `../qq-mcp/.env`，不替换既有连接凭据。
3. 修改 `group-bot/settings.json` 的 `group_id`、`chat_group_whitelist`、账号和模型，确认后开启 `enabled`。安装模板默认禁用回复；缺少的人设从 `persona-default.txt` 初始化为GPT 6 Luna白龙娘，回复规则从 `reply_protocol-default.txt` 初始化，已有个人/群级人设保留。
4. Windows 运行 `Start-QQ-Group-Bot.cmd`；Linux/macOS 运行 `sh ./Start-QQ-Group-Bot.sh`。启动 CLI 并打开 WebUI，终端也会显示地址。无图形界面时使用终端地址。

启动参数：

| PowerShell | Shell | 用途 |
| --- | --- | --- |
| `-CLI` | `--cli` | 只打开终端控制台 |
| `-SkipNapCat` | `--skip-napcat` | 连接已有/远程 NapCat，不代为启动 |
| `-Model 名称 -ReasoningEffort low -FastMode off` | `--model 名称 --effort low --fast off` | 校验并保存模型设置 |
| `-NoCooldown` / `-WithCooldown` | `--cooldown off` / `--cooldown on` | 明确调整冷却标记；不传则保留现状 |
| `-DryRun` | `--dry-run` | 仅显示计划，不安装、不启动 |

启动器从项目根目录定位文件，不依赖当前工作目录。优先使用 `.venv`，兼容已有 `qq-mcp/.venv`；也可用 `QQ_BOT_PYTHON` 指定解释器。PowerShell 入口支持 Windows PowerShell 5.1 / PowerShell 7；Linux/macOS 可用 `.sh` 或已安装的 PowerShell 7。

## WebUI 与 CLI

WebUI 左侧是群列表，右侧按群分为聊天记录（聊天气泡 + 执行过程）、运行状态、行为设置、人设与规则、群记忆；所有群总览、共享表情库和命令行在左侧栏底部。设置按用途分组，开关和概率直接拖动，每项都附中文说明。默认浅色主题，可切换深色模式。

- 会话列表按群名、群号搜索；对话流程按事件、角色、消息 ID、级别筛选。
- 事件详情显示触发消息、上下文 ID、引用原 ID、引用摘要、执行阶段与结构化结果。找不到引用时标记 `[引用记录未找到]`。
- 数据库和表情库支持查询与管理；修改、删除会影响 Bot 后续使用的数据。
- 删除本地对话记录会同时清除对应 Bot 上下文，不会撤回 QQ 消息。
- 日志展示执行阶段、模型返回的分析摘要与错误，不代表模型完整内部思考过程。

CLI 保留短命令匹配和 Tab 补全。常用命令：

| 命令或按键 | 用途 |
| --- | --- |
| `/help` | 从顶部显示完整命令清单，↑↓或PgUp/PgDn翻页，Esc返回；`/help config`、`/help member`、`/help system`查看详细参数，CLI与WebUI共用说明 |
| `/status` | 查看运行、队列与记录状态 |
| `/reconnect napcat` | 保存并重启当前群的HTTP连接，恢复暂停状态；不会重启QQ或其他群 |
| `/reconnect mcp` | 新建stdio MCP会话并读取当前群信息，验证MCP到NapCat链路；其他应用持有的MCP会话仍需在其宿主重连 |
| `/usage`、`/usage all` | 查询当前Codex账号5小时/1周额度、北京时间重置时间，以及当前群/全部群的实测token统计；60秒查询缓存 |
| `/config` | 查看或调整配置 |
| `/whitelist` | 管理授权群 |
| `/webui` | 输出链接并打开调试页面 |
| `/exit`、`/quit` | 保存待处理状态并退出调试后台及其工作进程 |
| ← / → | 切换群聊 |
| Ctrl+F | 搜索群名或群号 |

关闭浏览器页签不会退出后台。需要更新代码时，先 `/exit` 再手动启动；避免重复运行多个后台写入同一数据目录。

群页右上角提供“重连 NapCat”和“重连 NapCat MCP”。群Bot直接使用NapCat HTTP，MCP是另一条独立链路；单群暂停、群权限失败或启动中的状态，不代表QQ整体离线。重新连接当前群会先保存并停止其工作进程，再重新读取配置启动；其他群继续运行。MCP检查只新建本次验证会话并读取群信息，不重启QQ、不重启或接管其他客户端的MCP服务。意外退出的群后台延迟5秒重试；有STOP停止标记的退出仍保持暂停，不能自动恢复人工暂停。

## 配置保存与继承

在 WebUI 点“保存”会校验并写入磁盘，修改前保留备份。重启会重新读取配置，无需每次重新设置。

| 内容 | 保存位置 | 生效方式 |
| --- | --- | --- |
| 全局配置 | `group-bot/settings.json` | 所有群默认使用 |
| 群级覆盖 | `group-bot/group-config/<群号>/settings.json` | 只覆盖该群明确设置的字段 |
| 全局人设/回复协议 | `group-bot/persona.txt`、`reply_protocol.txt` | 所有群默认使用 |
| 群级提示词 | `group-bot/group-config/<群号>/` 下同名文本 | 为空时继承全局 |

群级输入框的灰色 placeholder 展示全局值，不代表已写入局部配置；重置覆盖后恢复继承。正在执行的任务保留启动时的配置，后续任务使用新配置。群白名单、启动路径等参数只允许全局设置。

可配置项包括名字和别名、模型、参与频率、主动开话题概率、@ 与引用回复概率、表情包选择、风格学习、上下文预算、调用限额与图片清理等。具体范围与含义以 WebUI 参数说明为准。

“参与频率”并不等于每条消息独立有同样概率必回；消息批次、对话对象、冷却、预算和近期互动共同决定是否回复。自动接话、主动开话题和发表情包是不同阶段的配置。

## 图片、记忆与本地数据

运行状态页提供“5小时 / 1周额度与token”查询。额度使用官方 Codex app-server 的只读 `account/rateLimits/read`，沿用当前 CLI 登录，不创建会话、不调用模型，不读取或向页面暴露登录凭据。显示服务返回的真实窗口、已用/剩余百分比和重置时间；接口未返回的窗口不补造，失败时标注错误及旧缓存。官方接口说明见 [Codex App Server](https://learn.chatgpt.com/docs/app-server)。

token来自本项目 Codex CLI 的 `turn.completed.usage`，持久化于 `runtime/token-usage.sqlite3`，保留32天。可查看当前群或全部群最近5小时/7天的滚动统计，也按账号当前额度窗口起止统计项目用量；输入包含缓存，合计=输入+输出，缓存不重复相加。账号额度跨客户端共享，项目token不能等同于账号全部用量；接口不提供剩余token总数时显示未知，不按百分比反推。历史调用无法补算；无usage的失败/超时及独立生图调用不计入。统计数据库请随运行数据一起备份。

缓存命中以CLI实测的 `cached_input_tokens`（或 `input_tokens_details.cached_tokens`）为准，未报告显示“—”，明确返回0才算未命中。旧版保存为0但无法证明字段存在的记录标为未知，正数保留为已报告。UI同时显示命中token、未缓存输入、命中比例和报告覆盖次数；覆盖不完整时，比例与未缓存输入只基于有缓存数据的调用，不把未知记录计为未命中。命中比例=已报告缓存token/这些调用的输入token，与账号剩余额度百分比无关。

模型请求使用稳定排序、按内容哈希命名的输出schema，消息/候选/证据ID不再逐轮嵌入传输schema，返回结果仍按本轮原始enum/const在本地复核；不合格结果不会绕过校验发送或写入账号资料。固定回复指令先于当前发言者身份规则和动态群聊数据。这里只改善可复用前缀，不缓存最终聊天答案，不保证服务端命中。可在后台查看schema指纹及每次实际token报告；未做额外模型调用来“预热”缓存。

状态页分别显示聊天窗口和执行日志窗口的字符量；两者各受 `console_max_text_chars` 限制，本地文字合计不与单个窗口上限相比较。模型实际输入仍单独受 `max_prompt_chars` 限制。

- 分析与回复共用话题上下文选择：显式引用优先；同账号的接续追问可在会话状态有效期内保留上一轮问答，避免被大群闲聊挤掉。它只是理解背景，不重放旧请求；重连历史不参与自动接续，屏蔽、指令和视频仅记录的边界继续生效。分析输入超预算时先移除无关闲聊，再压缩保护消息正文。

- 群聊繁忙时，当前回复生成与分段发送完成前继续积累新消息；下一轮将待接话的文字请求与普通新发言合成一次对话交给模型，不再逐条追赶。批次保留发送者、时间和消息ID，按总输入预算保留较新的内容，消费过的消息不会再逐条触发。独立绘图请求仍使用原来的绘图通道。后台积压图片优先自动读取最新一张，较早图片保留记录，需要时可通过当前请求或引用读取。

- NapCat断线时取消当前群尚未完成的回复、识图和学习任务；重连成功的首批消息及延迟补回的旧消息只写入历史存档，不执行旧指令、不补回复或识图。此后新到的消息才恢复AI处理；不会自动恢复已手动暂停的会话。聊天快照使用原子替换并对Windows短暂文件占用进行有限重试。
- 回复正文会整理空白分段和多余空行；超长、原始CQ码、代码围栏等仍会被拦下，日志区分具体原因及字符数，不记录模型原文。明确回复请求遇到无有效正文或表情时，在额外调用预算允许的情况下最多修复一次；修复失败不发送，不截断答案或绕过校验。

`max_prompt_chars` 是模型输入的字符预算，默认12800；`console_max_text_chars` 是调试记录队列的总文本预算，默认 12800 字符。近期聊天存档另有条数与时间限制，磁盘存档不会全部送入模型。

备份时保留 `settings.json`、个人提示词、`group-config/`、各群 `runtime*` 和 `shared-emoji-library/`。`.gitignore` 只是防止误提交，不会删除这些文件，也不能替代备份。已被 Git 跟踪的文件不会因新增忽略规则自动取消跟踪。

重新克隆只会取回源码和默认模板，不会取回被忽略的个人配置、聊天记录、记忆数据库和表情原图。更新源码前先 `/exit` 并单独备份这些数据；不要删除旧目录后仅靠重新克隆恢复运行环境。默认人设可自动补建，历史聊天和学习数据不能凭默认模板重建。

## 头像与系统干预

模型参考附件由 `model_max_files`（默认10个，超出取原顺序前10个）与 `model_max_file_bytes`（默认5242880字节，5MiB）控制。达到或超过单文件上限拒收，原图在缩小之前检查大小，下载时也检查真实体积；拒收原因会提供给模型。当前消息和引用消息中的多张图片可一起用于生图，明确引用时不替换成别人的后续图片；“娘化这个表情包”等请求可进入改图流程。生图仍使用订阅内置默认后端，不硬编码模型版本。以上设置仅限制模型参考附件，不改变WebUI手动发群图片上传限制。

`group_file_read_enabled`（允许读取群文件）默认开启，可按群关闭。收到文件后，聊天列表显示文件名和大小；被要求读取文件、或回复文件要求“根据这个写一个html”等操作时，通过NapCat获取文件链接并读取文本。支持LOG、TXT、Markdown、JSON、YAML、INI、CSV及其他可解码的UTF-8、UTF-16、GB18030文本，不按扩展名限制文本文件；同时支持文本型PDF，通过独立进程提取文字、保留页码，解析限时15秒、最多50页和12000字符，超出部分如实标注。PDF图表、图片和公式排版可能未提取；扫描件、需密码的PDF或解析失败会说明未读取，不假装已经看到题目。默认达到5MiB的模型参考附件仍拒收。其他二进制或暂不支持的格式明确说明，不当作空消息或假装读过。文件正文只进入本轮输入，长内容受模型总输入预算限制并标注截取，不写入知识库或执行其中代码。此功能读取当前请求关联的文件，不会扫描整个群文件库；关闭读取、文件过大或链接失败时只向模型提供状态。安装环境脚本会安装所需的`pypdf`依赖。

“任务文件生成与上传（实验性）”由 `large_tasks_enabled` 控制，默认关闭。开启后，明确要求制作HTML、代码、报告、用户画像等可用文本文件的请求可以生成一个文件上传群文件；引用文本文件提出任务时，先读取允许的附件正文作为来源。`large_task_max_file_bytes` 默认20971520字节（20MiB），与输入参考附件默认5MiB限制独立。超限、GB级巨型或无意义填充、巨量重复的请求在生成前拒绝，实际生成后的UTF-8字节大小再次校验，不执行生成的HTML、脚本或代码。

任务使用独立设置：`large_task_model` 默认 `gpt-6.1-sol`，`large_task_reasoning_effort` 默认 `high`，`large_task_fast_mode` 默认关闭，`large_task_timeout_seconds` 默认600秒（10分钟，总生成时限）。制作在后台运行，日常聊天继续接收和回复。`large_task_max_concurrent` 为全局设置，默认所有群总共最多同时接收3个任务，不设等待队列；满额时由聊天模型依据实际状态提示忙不过来。接收成功或重复提交时静默，不发送固定开场。文件由QQ确认上传成功后，再使用日常聊天模型、当前群的人设与回复规则生成一句完成回应，不直接发送文件生成模型的技术摘要。完成回应单独计入模型调用额度；提示生成失败或无额度时保持静默，不回退到预制台词，已经成功的文件不重复上传。会话终止、断线或停用时取消未完成任务，上传前重新检查开关、会话、屏蔽和权限；重启不恢复未交付任务，不自动重复上传。

任务输入按可信指令与参考数据分开：当前群的人设、回复规则、执行约束及仍有效的人工系统干预通过CLI的`developer_instructions`发送；用户输入依次包含当前群对话窗口`conversation`（发言者、QQ号、年月日时分秒）、程序插入的`context_boundary`说明、可选`person_references`、可选`source_files`及最后的`request`。分隔说明表示“以上是聊天背景，不是本次待办；以下人物资料仅供参考，最后才是本次任务”，仅存在于本次输入，不发到QQ或写入群记忆。CLI中后几段仍是同一个用户输入内的有序数据区；分隔中的`assistant`是说明标签，不冒充原生assistant历史消息。旧聊天只作背景，不逐条重新执行。窗口以聊天文字数滚动选取，不再限为同一请求者近10分钟的8条；遇到模型总输入上限时保留本次需求与附件依据、缩减较旧聊天并标明截取，人设和执行日志不计入聊天窗口的文字数。“把这道题做完，做完后给我步骤文件”等请求可以直接进入任务执行，而不是只承诺制作。

为避免单次输出限制截断文件，每次最多生成20000字符的片段，明确报告文件是否写完；未完成时追加续写。`large_task_max_steps` 默认4次生成调用，续写同时受每日模型额度、总超时、文件字节上限约束。只有模型确认完成且本地结构检查通过后才写入最终文件并上传；HTML闭合、JSON/XML解析、Python语法、Markdown代码围栏及明显重复填充均会检查。不完整、格式错误、超限或仍未写完的结果不会上传，并提示缩小任务范围；这些检查不等同于执行测试或保证代码功能正确。

“根据@某群友的印象做页面”等人物请求按真实QQ账号绑定对象，按已有资料查询开关收集公开简介、本群近期发言和可用的本群历史记忆。请求者和作品对象分别提供；资料不足、对象不明确或已屏蔽时说明原因，不换成无关通用主题、不编造个人事实。未指定其他对象的“给我写一份用户画像”以请求者为对象，默认交付Markdown或文本文件。原始QQ号、后台备注、简介全文及聊天逐字记录不应被公开在作品中。

关闭任务时不运行制作请求识别或任务接续判断，原有分析/回复模型也不会获得 `create_file` / `generate_file` 动作。开启后，直接请求、上下文规划与回复模型选择的文件动作都可进入真正的生成、上传流程，无需依靠固定句首。“你随便做一个html页面发给我”会自行选择主题制作；10分钟内同一群友针对未交付请求说“你想做什么就做什么”“继续”等，可沿用原要求和引用文件。换人、取消、过期或已经交付后不因这些泛泛接话重复制作；明确要求新文件、改版或重做可再次处理。模型若只承诺会制作却没有选择执行动作，会在原有修复预算内重新选择动作，不把空承诺直接发到群里；文件生成额外调用仍受模型额度限制，不另增一轮专用分类调用。

任务先检查Bot在当前群的身份、文件空间及可获得的上传权限；上传前再次检查当前开关、会话、屏蔽状态和权限。接口明确禁止上传、容量已满或Bot成员身份无法确认时停止；普通群员的上传权限字段缺失不代表禁止，不要求Bot必须是管理员，允许提交本次实际上传，由QQ返回结果确认。可选文件系统预检接口不支持时也不伪造权限拒绝。读取群文件列表成功不作为上传权限证明，上传成功前不向群里声称文件已经发出。文件通过 `base64://` 传递完整字节给NapCat，由NapCat在自己所在设备上解码并上传，可跨Windows/WSL，不依赖共享本地路径；成功确认后才发送完成说明。实际拒绝的错误码与原因保留在后台，失败、结果不确定或重启遗留的上传尝试均不自动重传。

传给模型的当前消息、历史消息、引用、合并批次与私聊记录都提供 `sent_at`（年月日、时分秒和数字时区偏移）。Unix时间按运行设备的本地时区显示，不写死北京时间。每次模型调用前刷新唯一的临时 `generation_clock`：Linux/macOS优先读取系统 `date` 原文，支持英文CST、日文JST等本地格式，Windows使用同类date风格；这只是生成前参考时间，不是预知的实际发送时间，不写入历史或群记忆，也不不断叠加旧参考。实际发出后优先保存NapCat返回的时间，没有时用本地发送完成时间，后续收到自身QQ回显时校准已有记录，不重复追加消息。历史引用的时间也保留；缺失时间明确标记未知，不根据当前日期补造旧消息时间。

点名识别只提供候选线索，不把别名命中伪装成QQ原生@或强制聊天。“身份与开关”中的 `name_match_sensitivity` 默认0.5（50%），越低越谨慎、越高越容易把模糊称呼送入语境判断。`at_context_sensitivity` 默认0.95（95%），通常回应@后的提问、求助和招呼；调低后更要求明确接话依据，名单、转述和顺带点名可以静默。两个参数范围0～1，可全局设置或按群覆盖，都是语境匹配倾向，不是随机丢消息。上下文分析分别记录消息是否对Bot说与话题对象是否为本账号、产品类别或他人；“没用过GPT/订阅GPT/用GPT写代码”不自动认作在使用或点名本QQ账号。明确称呼、原生@和引用仍可正常接话，普通水群也可以作为旁观者参与。

行为设置→其他的“是否启用拼音缩写猜测”（`pinyin_abbreviation_guess_enabled`）默认开启，可全局设置或按群覆盖。它在原有上下文分析与回复调用中结合缩写、重复音节、引用和语气判断，不使用固定释义词典，不额外调用翻译模型。可能展开与交际意图分开记录，猜测不视为对方原话，不自动升级为辱骂标签或屏蔽。没理解时避免硬夸对方“认真接话”，可自然短回、表情或旁观；没有要求翻译时不主动讲解黑话。关闭后停止相关提示与回复检查，模型原有语言能力仍保留。

模型总输入另受 `max_prompt_chars`（默认12800）限制，包含实际附入的人设、运行规则、当前消息、引用、近期对话和知识片段；界面的聊天窗口字数仍只统计聊天，不受知识库检索影响。知识库预算0表示检索全部匹配结果，不表示把全部正文塞进模型。群聊回复、上下文分析和私聊会保护当前消息和引用链，为最相关资料预留少量输入空间，优先压缩可选提示、表情候选及无关旧背景，再在剩余空间附入更多片段，避免“检索成功但模型一条也没收到”。JSON资料可按明确名称提取完整条目，稀有实体词优先于泛用词命中；超长片段保留来源并标记截取。不删除本地聊天记录，不改系统干预的当前窗口有效期。执行日志的 `Knowledge prompt budget` 与 `Knowledge role budget` 分别显示回复、上下文分析实际附入的片段数和字符量。已有资料足够时，“看看/查一下”不自动触发联网；联网仍必须有真实工具事件或匹配的已读正文才能认定成功。

模型查询资料与后台显示头像分别控制。在行为设置的“资料查询与工具”中，`model_avatar_query_enabled`（头像）与 `model_profile_query_enabled`（公开简介）均默认开启。只有直接询问某人的头像、签名、简介、昵称，或要求按照头像绘图时才查询；普通聊天、单独@和仅提到名字不会自动查询。支持本人、Bot、明确@的群成员、引用中的明确对象及唯一匹配的昵称；同名或对象不明确时先确认，不猜QQ号。简短的“那他呢”可沿用最近两分钟内同一人明确提出的资料问题，但仍须确认对象。

查询前检查群成员身份和屏蔽状态；私聊仅查看当前获准好友或Bot本人，不把其他好友资料搬进当前私聊。只使用接口实际返回的公开昵称、群名片、简介/签名，不读取年龄、性别、电话等字段，不把后台账号说明冒充QQ简介。部分NapCat版本不会返回简介，这时明确标记“接口未提供”。简介按会话与账号缓存300秒，`profile_query_cache_seconds=0`可停用缓存；关闭查询后不再使用缓存。头像实际下载成功后才作为附件交给模型，私聊还需开启“私聊识图”。私聊默认与每个联系人也有独立的查询开关。

`tool_workflow_enabled`默认开启“先查询资料，再绘图”：用户明确要求先查或按链接资料绘图时，先读取链接/取得联网证据，再将有来源的外观事实连同原始需求、参考图交给内置生图。没有证据、超出步骤或模型额度、会话停止时终止，不假装已经查过。`tool_workflow_max_steps`默认4（读链接、联网整理、绘图各占一步），各阶段仍受已有超时限制；不开放任意命令或MCP执行。普通绘图不额外查询。联网回答按问题复杂度提供信息，`web_answer_max_chars`默认300，可设20～2000。

群列表、群总览和消息头像支持显示真实 QQ 头像。启用 `avatar_remote_enabled` 后，本地调试服务向腾讯 `qlogo.cn` 提交群号/QQ号获取头像，不提交聊天内容。成功结果本地缓存5分钟，页面每30秒检查可见头像是否到期；当前群顶部“刷新头像”可绕过本地缓存重新获取。刷新先保留旧图，新图解码完成后原位替换，失败继续显示旧图；从未成功获取时使用默认字母头像。关闭联网后仍可使用有效本地缓存。腾讯头像源自身的更新延迟无法由本地刷新强制消除。

聊天页工具栏提供“系统干预”，筛选栏提供“只看系统提示词”。系统干预是操作员控制数据，通过 Codex 的 [developer_instructions 指令通道](https://learn.chatgpt.com/docs/config-file/config-reference#developer_instructions) 注入，和群友发言分开；提交不创建待回复消息、不立即调用模型、不向 QQ 发送消息，也不加入群聊记忆和表达学习。

- 范围：默认当前群，可选择所有当前已授权的群；之后新增的群不会自动继承旧干预。
- 默认有效期：当前对话文本窗口。按 `console_max_text_chars`（默认 12800 字符）计算，干预后产生的聊天文字将其挤出窗口时失效；执行日志、历史回放不消耗有效期。修改窗口大小会重新判断是否到期。
- 可选有效期：下一次成功的自然回复、定时失效、直到手动清除。下一次回复模式在发送成功且使用了该干预后消耗；失败或旁观不会消耗。
- 查看与清除：系统提示词筛选显示干预内容、生效/失效/清除/使用状态；干预面板可以清除单条或当前群所有生效项。有效期与审计记录保存在各群运行目录，重启不会自动重置。
- 输入预算：生效的干预计入模型输入字符预算；已有生成任务使用创建时的指令快照，后续自然触发的任务采用新内容。

CLI 支持短命令与 Tab 补全，例如：

```text
/system add 接下来少用括号，接当前话题
/sys list
/system add --scope all --mode timed --minutes 30 先不要主动开新话题
/system add --mode once 下一次回复只说重点
/system remove 完整干预ID
/system clear
/system clear --scope all
/view system
```

新安装代码后，在旧 CLI 输入 `/exit`，再手动运行 `Start-QQ-Group-Bot.cmd` 加载后台功能。只刷新页面不能替换已加载的 Python 后台代码。

## 底部输入框与手动消息

聊天记录底部常驻输入框默认发送系统干预，可切换为当前角色的“消息（发到群）”。Enter 发送，Shift+Enter 换行；草稿按群和类型分别保留。系统干预可选择范围和有效期，默认当前群、当前对话窗口，不立即触发模型或 QQ 回复。

系统提示词列表和管理面板可逐条“删除”，删除后从列表隐藏并停止影响后续任务；本地保留删除审计，已经开始的任务仍使用创建时的快照。CLI 支持 `/sys delete 干预ID`；`remove` 停用单条，`clear` 停用生效项。

手动消息以当前群 Bot 的身份原样发送，不经过模型改写，最多 2000 字符。需要已加载此功能且在线的群后台；排队超过 5 分钟不再发送。界面区分排队、已发 QQ、本地记录待补写和成功；发送结果不明时不会自动重发，请先核对 QQ。

“消息（发到群）”支持点击“上传图片”，也可在输入框直接粘贴剪贴板图片；支持 PNG、JPEG、GIF、WebP，最多 2 张，单张不超过 5 MiB、合计不超过 8 MiB。选图后显示可放大、可移除的预览，并在光标处插入 `[图片1]`、`[图片2]`。例如 `文字[图片1]然后[图片2]` 会按此顺序组成同一条 QQ 消息；没有占位符的附件会追加到末尾，也支持只发图片。GIF 保留原始动画。附件草稿按群隔离，切换系统提示词时不会发送附件。

消息下方及详情提供“回复”和“@ 发送者”；输入框旁的“@ 群友”可按昵称、额外昵称或 QQ 号选择，输入框在行首或空白后输入 `@` 也会打开选择器。选择后插入 `[@QQ号]`，发送时转换为原生 QQ @，最多 8 位，不支持 @ 全体。引用目标和 @ 均可单独取消，按群保留草稿；可以与文字、图片同条发送。手动消息的引用摘要和 @ 信息会进入聊天上下文及本地记录。仅有 `[@QQ号]` 文本而未在界面选择群友时，按普通文字发送。

上传图片通过受密钥保护的本地 WebUI 接口校验和排队，发送时使用图片内容，不要求 NapCat 访问本机文件路径。成功后原图进入长期图片缓存，供聊天记录查看；它与 AI 生图临时目录分开。上传暂存副本在发送、归档和本地记录完成后删除，后续归档保留期限按图片记忆策略管理。

发送成功后写入最近聊天存档、当前上下文以及群数据库的 `manual_messages` 表（数据库查看页名称“Bot手动消息”）。消息按 Bot 发言记录，不冒充群友学习样本；QQ 回显按消息 ID 去重。长期结构化记录保留 30 天，当前上下文仍受窗口和条数限制。CLI 可使用 `/say 消息内容`。

这些入口需要更新后的 WebUI 和群后台一起运行。更新后手动在旧 CLI 输入 `/exit`，再运行 `Start-QQ-Group-Bot.cmd`。

## 图片原图、人工摘要与表情收录

点选聊天图片消息后，右侧图片详情提供“查看原图”“修改摘要”“收录表情包”。共享表情库还提供“手动录入表情包”，可上传 PNG、JPEG、GIF、WebP（上限 2MB），填写名称、说明、情绪和适用场景；收录方式可选人工确认直接入库或交给自动审核。

- 原图和缩放识图附件分开保存：原始字节放在各群 `runtime*/image-originals/`，按内容 SHA-256 去重，使用相对路径并保留 GIF 动画。识图压缩不会替换原图。
- 查看原图优先使用本地文件；旧消息未缓存时，只从该群对应 QQ 消息的指定图片组件重新读取，校验内容哈希。原消息不可读或哈希不一致时明确报错，不用其他图片替代，也不触发模型或 QQ 回复。
- 普通群原图跟随图片识别滑动窗口回收（默认 2000 条消息，近期写入有短暂保护期）；人工入库的表情另存到 `shared-emoji-library/`，不受群图片窗口或 AI 生图 temp 定时清理影响。
- 人工摘要独立保存到 `runtime*/image-summary-edits.json`，修改前备份到 `image-edit-backups/`，覆盖自动摘要的优先级更高。后续自然回复、同图复用和当前聊天上下文使用修改结果；保存不立即回复、不增加出现次数，也不改变原有 2000 条消息有效期。摘要修改只影响当前群。
- 人工确认收录直接覆盖自动审核拒绝，原图复制到共享表情库，所有授权群可用；这与修改识别摘要是两个独立操作。人工收录不调用模型、不立即发表情。
- 更新后仍在执行的回复保留已取到的数据；后续任务使用新摘要。备份个人数据时请完整保留 `runtime*/` 与 `shared-emoji-library/`，包括原图及人工修改文件。

控制台新增 `/stop`，与 `/exit`、`/quit` 相同，保存记录后停止群后台与 WebUI。第一次加载此更新请使用旧版本已支持的 `/exit`，再手动打开 `Start-QQ-Group-Bot.cmd`。

## 人工收录时 AI 识别填表

从聊天图片收录、或在共享表情库上传图片时，人工收录弹窗均提供“AI 识别填入”。点击后使用当前群配置的识图模型（未单独配置则使用回复模型），填入表情名称、图片说明、情绪和适用场景。GIF 会取不同帧供识别。

识别只生成建议，不自动点击保存、不修改识图摘要、不收录、不发送 QQ 消息。完成后弹窗保持打开，仍需操作者检查并手动保存；等待期间手动修改的字段会保留。识别期间暂时禁用保存，换图、关闭弹窗或取消时丢弃旧结果。

需要已加载此功能且在线、启用的群后台。每群同时处理一个填入任务，每次占用已有每日模型调用额度一次；任务通过后台异步处理，CLI 和 WebUI 不等待模型完成。排队超过 3 分钟失败，单次模型超时上限 45 秒；后台重启不会重试旧任务。输入图片在完成、失败或取消处理后删除，任务结果最多保留 24 小时。

更新后手动 `/exit` 或 `/stop`，再启动 `Start-QQ-Group-Bot.cmd` 加载新 WebUI 与群后台。

## 聊天图片显示与组合回复

聊天图片可以双击气泡在原图与文字摘要之间切换，也可使用气泡下的“显示图片/文字”按钮；“放大原图”单独打开原始文件。行为设置 `chat_image_display` 可选 `image`（默认图片/表情）或 `text`（文字摘要），支持全局默认和按群覆盖。单条消息的临时切换只影响本次页面，不改聊天文本、识图记忆或模型上下文。图片按需加载、最多三个请求并行，原图失效时保留摘要与重试入口。发送后的图片也可预览；引用中的摘要仍留在引用栏。

普通回复支持多条文字后跟多张表情：`max_reply_parts` 默认 6（范围 1～10），`max_stickers_per_reply` 默认 3（范围 1～5），两项均支持群覆盖。总文字仍受 `max_reply_chars` 限制，条数是上限，不要求凑满。模型按自然停顿给出 `text_parts`，按情绪和用途选择候选 `media_ids`；正文先逐条发送，表情随后逐张发送。不会再因跟图把文字压为两条，也不在模型选好分段后再次抽签合并。`burst_reply_probability=0` 时文字合为一条，正值只影响分段倾向。

`at_reply_probability`、`quote_reply_probability` 默认仍为 0.5。每轮有效回复只抽一次，命中后真正使用 QQ 的 at/reply 组件，不再只当作“允许模型选择”的概率。模型可以选本轮真实消息的发送者作为 @ 对象，未选其他人时指向当前回复对象；不编 QQ 号、不 @ 自己。@ 和引用只附首条；纯 QQ 商城原生转发表情无法承载这些附件时，不另发一条空 @。

表情只从本轮可见、已收录且可用的候选解析，去除重复 ID/内容；使用次数在对应表情真正发送成功后更新，每张分别计数。上下文以带括号的 `[表情包：说明]` 记住已发表情，不把内部说明发进 QQ 正文。后台的 `reply_delivery` 与 `delivery_queue` 决策分别显示分段规划及实际出队条数、表情 ID、引用目标和 @ 对象，方便排查“规划了但没发”。

每条都检查停止状态和消息额度，逐条写入存档并保存发送状态。连接中断或重启后不补发旧尾部，发送结果不明时停止自动重发。参考 MaiBot 的语义断句、文字附件解析及逐段发送设计，在现有一次回复调用中完成组合规划，不额外增加断句模型调用；角色遵循当前选定的人设。参考来源：[断句](https://github.com/Mai-with-u/MaiBot/blob/main/src/chat/utils/llm_sentence_splitter.py)、[回复与附件](https://github.com/Mai-with-u/MaiBot/blob/main/src/maisaka/builtin_tool/context.py)。

更新后在旧 CLI 手动 `/exit` 或 `/stop`，再打开 `Start-QQ-Group-Bot.cmd`；只刷新页面不能加载新的 Python 发送逻辑。更新不会改写已有全局/群设置、头像授权或清理模式。

## WebUI 监听、滚动窗口和消息去重

全局配置新增：

```json
{
  "webui_host": "127.0.0.1",
  "webui_port": 0
}
```

默认仅本机监听，`webui_port=0` 自动分配端口；可设 1～65535 的固定端口，占用时明确报错。`webui_host` 接受 IPv4/IPv6 地址，例如 `0.0.0.0`（所有IPv4接口）、`::`（所有IPv6接口）、`::1`。浏览器访问IPv6时使用 `[地址]:端口`。通配监听时 CLI 的本机链接使用回环地址；其他设备使用本机实际IP和同一端口，并带 `/webui` 提供的 `#key=...` 访问密钥。Host 仅接受对应IP地址，变更操作仍需密钥及同源校验。这两项只在全局设置，保存后退出重开 Debug 才更换监听。

聊天与执行日志各自使用 `console_max_text_chars`（默认12800）和 `console_max_records` 的滚动窗口，超限逐条移除该类最旧记录，日志不再挤掉聊天。WebUI 和 CLI 还会只读合并近期聊天存档，以补回旧版本被日志挤出但仍存在存档中的消息；人工删除的记录不会恢复。模型输入预算、长期数据库和近期存档容量仍分别管理，达到显示窗口上限不会清空它们。

新消息、图片剩余有效期等元数据变化时，聊天列表复用已有消息与图片节点，只更新变化项，保留图片/GIF和手动图片/文字选择。默认显示方式为图片/表情包。下拉选项面板与明暗主题统一，保留键盘选择；表情库和数据库分页支持输入页码后点击跳转或按回车。

QQ 原生表情转发成功但没有返回消息ID时，发送确认只记执行日志，聊天以随后QQ回显的真实消息为准，避免两条气泡及空ID原图重试。已返回ID的发送会立即写入去重集合；每张表情的使用次数仍只计成功发送一次。已收录的普通图片也按表情身份匹配，不依赖QQ把 `sub_type` 标为1。没有额外文字/识图问题的已收录表情优先选择匹配表情接话，不写配图点评；没有适用表情可沉默，明确问图时仍回答问题，关闭纯表情配置时仍尊重配置。

上下文/情绪分工遵守 `role_timeout_seconds`（3～30秒，且不超过聊天模型超时）；视觉分工独立使用 `vision_timeout_seconds`（默认60秒），不再暗中把情绪/视觉截为12秒。后台降级日志包含原因、实际超时预算和脱敏错误详情，单个可选分工失败不会向群里发送故障话术。

更新完成后手动 `/stop` 或 `/exit`，再启动 `Start-QQ-Group-Bot.cmd`。代码更新不主动重启服务，不改已有群配置、人设、聊天数据库和表情资产。

## 群友标记、额外昵称和聊天输入

点击聊天中的群友头像打开资料弹窗，手动选择 **AI / bot / 真人**，设置额外昵称和账号说明。例如 `千柒, aaaa`，逗号或换行分隔，最多10个昵称，每个最多40字。昵称绑定QQ号，不替换QQ昵称或群名片；后续身份识别和对话可据此理解称呼，同名仍按账号区分。另有“群友标记”页用于搜索、查看自动证据和管理未显示在聊天中的账号。仅对当前群生效，持久保存在 `runtime*/member-labels.json`。

手动标记优先；恢复自动判断会移除人工覆盖，清除标记会同时移除判断记录，保留额外昵称；昵称输入框留空保存可单独清除昵称。自动标记只推断指令 bot，不靠文风猜AI或真人：默认在最近200条群消息中，同一前缀累计10次独立指令响应。支持 `/xxx`、`!xxx`、`！xxx`、`.xxx`、`y查分`、`y help` 等开头形式，可配置其他前缀；全半角同类前缀合并计数。只累计指令的响应者，不把发指令的人直接标成bot；同一条指令的多次输出只计一次。响应须在60秒内，优先匹配引用/@，无引用图片须只有一条明确的近期指令，普通文字须紧接唯一指令；歧义场景不计。自动结果带证据，供后台纠正。`member_auto_bot_marking_enabled`、`member_auto_bot_window_messages`（默认200，20～2000）、`member_auto_bot_min_observations`（默认10，至少2且不超过窗口一半）和 `member_auto_bot_command_prefixes` 可全局/按群设置。轻量判断窗口独立持久化，不受模型上下文字符裁剪影响，重启继续累计；证据滚动移出窗口，已经确认的自动标记保留到手动清除，清除后从新响应重新累计。达到阈值仍只是推断，不主动在群里宣布。

聊天输入框使用 **Enter发送，Shift+Enter换行**，兼容Ctrl+Enter；中文输入法组合输入期间不发送。输入框placeholder和下方提示均说明快捷键。系统提示词的发送仍只写后台，不立刻触发QQ回复。

未收录的纯图片/表情在没有识图提问时也只选择合适表情或旁观，不写画面点评；无候选、配置禁用或没有适用表情时可静默。明确问图或以图片为背景另有文字问题时保留正常回答。群列表按群号复用头像和按钮节点，新消息、名称、状态更新不会反复重建头像。

Python文件锁、CLI键盘、进程组退出已增加POSIX实现，Windows仍使用原生Job/字节锁。Windows任务计划清理仅供Windows，其余平台使用间隔、每日或逐图到期清理。已添加Windows/Linux/macOS离线检查工作流；本机实际验证是Windows，Linux/macOS安装和QQ实机行为仍需对应平台验证。

## 模型阶段超时

全局及群级配置支持 `model_timeout_seconds=30`（文字聊天）、`vision_timeout_seconds=60`（识图）、`image_timeout_seconds=150`（绘图），单位秒。图文在同一次模型调用中使用30+60=90秒；识图后绘图的阶段预算合计60+150=210秒；同时还需要文字时是60+150+30=240秒。只使用实际参与的阶段，不按图片张数重复累加。

纯视觉分工、后台识图、表情审核和人工AI识别填入独立使用识图预算，不会再被聊天30秒或上下文/情绪分工上限提前截断。串联阶段分别计时，不用一个30秒超时包住整个混合任务；辅助分工判断、排队、下载、清理进程等仍有各自耗时，阶段预算合计不是严格的端到端耗时承诺。超时只记后台失败，遵循原有静默失败设置。

## 群友资料的模型参考与自行标记权限

“后台说明”现统一称为“账号说明”，原有说明直接沿用，不迁移或清空资料。

行为设置新增两个分组，均支持全局默认及当前群覆盖：

| 资料 | 可供模型参考（默认） | 允许模型自行标记（默认） |
| --- | --- | --- |
| 账号类型 | 开启：`member_reference_type_enabled` | 关闭：`member_model_type_enabled` |
| 额外昵称 | 开启：`member_reference_aliases_enabled` | 关闭：`member_model_aliases_enabled` |
| 账号说明 | 开启：`member_reference_note_enabled` | 关闭：`member_model_note_enabled` |

参考开关只影响模型输入，不删除后台资料；关闭额外昵称参考时，也不再把该昵称的解析关系提供给模型。只提供当前对话涉及的账号资料，说明最多200字；输入预算不足时可裁剪说明，实际聊天中本来出现的内容不因开关而删除。账号说明是资料，不作为系统指令执行，也不主动向群里播报。

自行标记是独立的写入权限，默认三项均关闭。开启后，在正常上下文判断或主回复调用中通过结构化 `member_updates` 提议修改，无额外常驻模型任务；每轮最多3项，须引用实际发言，证据发言者QQ必须与目标账号一致。只接受已开放字段和有效类型/昵称/说明，模型来源与人工来源分开保存，并记录证据消息ID。人工资料以及手动清空的昵称、说明优先，不被模型覆盖。即使不向群里回复，也可保存有效资料更新。

指令前缀及重复响应的行为规则独立由 `member_auto_bot_marking_enabled` 控制，不调用模型。模型自行标记开关不会隐式改变这条规则。更新后手动 `/stop` 并重新启动 `Start-QQ-Group-Bot` 以加载新代码。

## 群友屏蔽、bot主和类型提示词

点击群友头像，在“群友资料与标记”里设置 AI / bot / 真人 / bot主，并可单独设置“屏蔽（黑名单）”。类型标记和屏蔽互相独立。屏蔽只在当前群生效，不向QQ群宣布，不踢人、不禁言、不撤回消息；WebUI、CLI仍保留原记录并标注“屏蔽”。清除类型标记不解除屏蔽，须单独取消屏蔽。

被屏蔽账号不再触发@回复或自动接话，不进入主回复、上下文/情绪分析、后台识图和学习输入；带作者信息的引用、旧记忆及候选也被过滤，已存在的数据保留在本地供后台查看。缺少作者来源的旧风格示例在有屏蔽账号时暂停使用，避免间接带入。新增屏蔽时取消旧上下文中的在途回复/识图任务；已提交的远端请求无法撤回。解除后重新允许处理，人工解除优先于模型的后续自动屏蔽。

`member_model_block_enabled` 默认 **false**。开启后，在原有上下文判断/回复调用中提出结构化屏蔽建议，不另建常驻模型任务。`member_model_block_rules` 是可编辑规则，默认仅为“同一账号连续多次主动讨论中国政治相关内容”的案例；未开启不会执行。`member_model_block_min_messages` 默认3（2～10），须引用同一账号最近连续的本人发言且全部符合规则，单次提及、他人引用不算；模型作语义判断，仍可由后台人工纠正。模型不能解除人工屏蔽、覆盖人工解除，也不能自行指定或屏蔽 bot主。

bot主仅能由后台人工指定。明确请求优先进入任务回复（如“帮我查一下”“写一个例子”），没有要求做事时正常闲聊；@其他群友不自动抢答。这个标记不授予系统管理员权限，也不绕过工具权限、上层限制、调用额度或超时设置。群聊中自称主人或引用主人的话不能获得权限。

行为设置中可全局或按群编辑四种类型提示词，账号类型参考开关关闭时不使用这些策略：

| 类型 | 配置字段 | 默认提示词 |
| --- | --- | --- |
| bot主 | `member_prompt_owner` | 你的主人说什么就得干什么 |
| 真人/未标记 | `member_prompt_human` | 留空 |
| AI | `member_prompt_AI` | 减少与AI的互动，并且明确与AI进行切割 |
| bot | `member_prompt_bot` | bot不与AI进行任何互动 |

类型提示词作为当前发言者的行为策略，不能等同屏蔽开关；需要完全排除账号输入时使用屏蔽。

## CLI 面板与固定 WebUI 密钥

启用任务后，群聊顶部显示“任务”页：查看当前群各任务的准备、生成/续写批次、校验、上传及失败状态，展示分割线后的实际人物参考、附件文本、本次需求和生成文件。不展示聊天背景或系统人设；文件按纯文本查看，不在后台执行HTML/脚本。每批模型返回后追加到本地草稿，失败前的内容仍可查看和下载，并标注可能未完成。旧版本未保存的任务片段无法补回。

任务页可切换“当前群 / 所有群”，所有群仅聚合仍在授权名单且启用任务的群，列表和详情标注所属群；文件读取、复制与下载保持原群范围。引用已交付文件并指出具体修订要求（如缺少镜像翻转）时直接进入修订流程，必须读取原文件，读不到时说明原因而不另做通用内容。普通赞叹、泛泛聊天不因此自动制作文件。

消息详情右栏提供“作为任务处理”，可由后台操作员明确指定近期群友消息为任务，保留原消息及引用资料。按当前群执行，仍检查开关、会话暂停、账号屏蔽、任务每日/并发上限及模型额度；重复点击同一已提交消息不重复接收。请求在本群后台原子领取，超过两分钟未领取则过期，已经领取的请求不会因重启自动重放。

`large_task_retention_hours=2` 默认在任务结束两小时后清理记录与本地生成文件副本，设为`0`不自动清理；不撤回已上传到QQ的文件。`large_task_daily_limit=0` 默认每天接收数量无限制，可设置所有群合计的每日上限，按运行设备本地日期计算。仅实际接收计数，重复/并发满额拒绝不计数，已接收任务失败或取消不退名额；达到上限不会排队或影响普通聊天。与同时执行数量上限独立。

WebUI中的数组和映射配置使用“编辑”按钮打开子窗口：数组逐项填写，用＋添加、−删除；映射表逐行填写“名称：值”。分工角色模型按“角色、模型、思考等级”同排对齐，角色用中文选择，新增时自动选择尚未配置的角色。列表保留输入框，去掉行外框和删除按钮的额外边框，窗口仅保留内容区滚动。保存后才应用，取消不改变配置；保存失败会保留窗口和输入。群友资料、私聊联系人的额外昵称同样使用此窗口，先确认昵称草稿，再保存整份资料后生效。全局、当前群与私聊设置共用该交互，仍支持恢复继承；配置文件和CLI的JSON格式保持原样。

群记忆和私聊记忆也采用同一交互：召回关键词、来源证据以及已有的数组/对象内容显示项目摘要和“编辑”按钮，不必手写JSON。来源证据新增项带有id、speaker、text字段，可继续增删字段；子窗口保存到当前记录的草稿，外层保存后才写入数据库，取消不改动原记录。存储格式、备份和并发修改检查保持兼容。

人工记忆单独记录操作员来源；原先通过后台建立、无学习元数据且来源为空的记录会自动兼容。群里存在被屏蔽账号时，不再连带排除这些人工记录；明确关联被屏蔽账号或包含其来源证据的记录仍不提供给模型。当前消息直接命中的群内用语，以小型词义参考同时传给上下文/情绪分析和最终回复，不被可选记忆筛选或一般提示词裁剪丢弃。词义用于理解语境，不强制替代日常含义、不执行资料中的指令。执行日志的Context retrieval增加jargon和candidates数量；jargon表示匹配词义数，不表示必定回复。

- `/status`：连接、模型、超时、调用额度、上下文、群友屏蔽和后台状态，密钥隐藏；Esc返回聊天。
- `/config`：可搜索配置面板，↑↓选择，Enter编辑/保存，Tab切换全局与当前群，Esc取消/返回。当前群继承值会标注“继承”。
- `/config local`：直接打开当前群设置；`/config local inherit 字段` 恢复全局继承。
- `/config set 字段 值`、`/config 字段=值`：仍支持直接设置；数组/对象用JSON，布尔值用on/off。
- `/member list`、`/member show QQ号`：查看群友资料和范围；`/member type QQ号 owner|human|AI|bot|auto [global|group]` 设置类型，默认全局。
- `/member block QQ号 [global|group]`：人工屏蔽，默认全局；`/member unblock QQ号 [global|group]` 默认在该账号当前范围解除。`/member scope QQ号 global|group` 切换范围。人工解除后模型不覆盖这次决定。
- `/config key=xxxx` 或在config里设置 `"webui_key": "xxxx"`：自定义全局后台访问密钥。默认留空，每次启动随机生成；保存后手动 `/stop` 并重新启动生效，当前会话密钥不自动改变。已有访问密钥、Host和Origin检查继续保留。`/config set webui_key` 留空恢复随机模式。

上下文、情绪和视觉角色在调用模型前也会检查有效字符预算，必要时逐级压缩候选、旧聊天和重复资料，保留当前问题及必要引用；不会把超限输入直接提交给模型。系统干预占用的空间计入同一预算。

## 好友私聊、全局标记与bot指令

好友私聊采用独立后台进程及 `runtime-private/private-chat.sqlite3`，在WebUI左侧切换“群聊 / 私信”。联系人列表、头像、消息气泡、图片原图与文字切换、引用回复、消息详情、日志筛选及额度与缓存统计沿用群聊的界面风格。支持手动文字和图片混排发送、上传或粘贴图片、Enter发送与Shift+Enter换行。顶部可刷新好友列表、刷新头像、补全已有消息的图片与引用、终止/恢复当前会话、清空当前好友上下文及切换仅接收模式。刷新好友列表会重新查询NapCat，但不会重放历史消息。

私聊记忆使用每个联系人的 `runtime-private/contacts/QQ号/group-memory.sqlite3`，复用群记忆的表结构、搜索分页、随机编号及新增/编辑/删除/刷新，并在修改前备份。新消息可用于独立私聊记忆学习；只检索当前联系人的私聊记忆。群聊印象仍是只读参考。知识库改为表格管理，支持搜索、启用状态筛选、分页、增删改、导入文本文件（JSON/YAML/INI等均按文本读取）；导入不设文本字数上限，交给模型时仍受输入预算控制。

行为设置补充头像显示、聊天图片默认显示、长期记忆学习、分工角色模型及模型参考附件限制，均可设置私聊默认值和联系人覆盖。角色分析默认关闭，开启后的额外调用计入私聊模型额度。私聊不会触发群聊主动话题计划。默认不开启私聊，设置 `private_reply_enabled=true` 后，只接入QQ好友且同在已启用授权群的联系人，陌生人/临时会话不接入。群管理、群文件上传等仅适用于群的功能不在私聊页面显示。更新后需手动重启控制台和私聊后台，再刷新浏览器。

这些默认值均可在配置文件或行为设置中调整：

| 字段 | 默认 | 用途 |
| --- | --- | --- |
| `private_use_group_impressions` | `true` | 参考该好友本人有证据的群聊印象，可按联系人关闭；不搬入其他群友的原话 |
| `private_access_mode` | `all` | `whitelist` 切换为只允许私聊白名单 |
| `private_user_whitelist` / `private_user_blacklist` | `[]` | QQ号数组，黑名单优先，名单不能绕过好友及共同授权群要求 |
| `private_reply_cooldown_seconds` | `8` | 回复冷却，范围0～300秒，可按联系人覆盖 |
| `private_max_replies_per_hour` | `60` | 所有私聊共享，含手动发送 |
| `private_max_model_calls_per_day` | `200` | 所有私聊共享的每日模型调用上限 |
| `private_max_reply_chars` | `600` | 每条回复字数上限 |
| `private_vision_enabled` | `true` | 只读取本轮实际附带的好友图片 |

发送前会重查当前名单、屏蔽和配置权限；发送超时、崩溃或缺少消息ID时记为结果不确定，不自动重发。私聊默认的接入、额度和冷却参数保存到 `settings.json`，联系人覆盖及专属资料保存在私聊数据库。

群友资料弹窗直接提供“全局 / 本群”切换，保存时按当前账号生效，不改变其他账号的范围。新标记与新屏蔽默认选全局，已有标记打开时显示原范围；新勾选屏蔽时默认切到全局，若已手动选择本群则保留选择。全局在所有群和私聊共用该QQ号的类型、昵称、说明及屏蔽状态；切成本群后恢复各会话独立标记，本次资料只写入当前群，原来的独立资料保留。私聊页可选“全局 / 仅当前私聊”。切换后需点击保存，期间不会改动实际资料。`member_labels_global_enabled` 仅控制未单独指定范围的旧标记、规则和模型标记，默认关闭，不再覆盖手动选定范围。指令机器人的观察窗口仍按群分别累计。不另设主人称呼功能，沿用已有额外昵称。此次更新涉及后台存储，需手动退出并重新启动控制台；旧后台未重启前，新页面会提示并阻止保存范围，避免选择未生效。

`owner_commands_enabled=false` 默认关闭bot聊天指令。开启后，仅后台人工指定且未屏蔽的bot主可以在聊天中使用CLI命令，默认前缀 `owner_command_prefix="/"`，可改成 `!`、`.`、`y` 等。收到后先回执，CLI执行完成后把结果回传到来源群或来源私聊，包括 `/usage` 的额度、token与缓存统计。发送前重新核对权限和屏蔽状态；长结果按最多4条、每条3000字符拆分，超长部分提示到CLI查看；密钥等凭证隐藏。发送超时或结果不明确时不自动重发，不补发超过两分钟的旧结果。会话暂停不影响控制结果；仅接收模式仍不向群发送结果。界面和回执统一称“bot指令”，现有 `owner_*` 配置键保持兼容。`owner_command_aliases={}` 默认沿用CLI命令名；例如配置：

```json
{
  "owner_commands_enabled": true,
  "owner_command_prefix": "/",
  "owner_command_aliases": {
    "清空": "session clear",
    "恢复": "session resume",
    "概率": "config local set passive_probability"
  }
}
```

群里发送 `/概率 0.05` 等同CLI的 `/config local set passive_probability 0.05`。`/session stop`、`/session resume`、`/session clear` 按来源群执行，不影响其他群。私聊中的会话操作只作用于当前联系人。其他命令保留CLI本身的作用范围，例如 `/stop` 会退出整个控制台，`/config global ...` 修改全局；路径和主群编号仍按CLI校验要求停机修改。配置及命令结果只保留在鉴权后台，不将密钥或人设内容回显到QQ。修改权限后排队指令会重查权限，崩溃后不自动重放已经开始执行的指令。

## NapCat正向HTTP / WebSocket与MCP

`napcat_connection_mode="current"` 默认沿用本机 `napcat.env` 的连接地址和令牌，不改变已有连接。可设置 `http` 或 `ws`，通过 `napcat_host`（IP/IPv6/域名）、`napcat_port`、`napcat_path`、`napcat_secure` 和 `napcat_token` 自定义连接。主机/路径/令牌留空、端口为0时继承当前配置；API超时 `napcat_timeout_seconds` 默认30秒。需在NapCat开启匹配的HTTP或WebSocket服务端。本项目主动连接NapCat，WebSocket以echo匹配API响应并跳过推送事件；连接中断后下一次请求重新连接，不重放失败请求。[OneBot正向WebSocket协议](https://github.com/botuniverse/onebot-11/blob/master/communication/ws.md)

NapCat MCP默认跟随Bot当前连接；`napcat_mcp_url`、`napcat_mcp_token` 默认留空，可显式覆盖。CLI `/reconnect mcp` 使用这组配置建立新会话；外部MCP宿主可将stdio启动入口配置为使用QQ MCP虚拟环境的Python运行项目根目录 `tools/napcat_mcp_stdio.py`，每次启动重新读取配置及授权群。外部应用已经运行的MCP连接需要在其宿主重连。

WebUI按钮与CLI对应：仅接收 `/receive on|off`，刷新头像 `/avatar refresh`，重连 `/reconnect napcat|mcp`，终止/恢复 `/session stop|resume`，清空上下文 `/session clear`。`/help`、Tab补全及 `/status` 同步更新。更新代码后手动退出并重新启动控制台以加载Python和私聊后台；本次接入参考了提交包的私聊实现，未接入独立主人称呼或原有的全局清理记忆指令。
